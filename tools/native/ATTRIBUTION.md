## Safeguards and evidence boundary

- **User-selected proxies:** The [application SOCKS socket policy](https://github.com/0cwa/collieim-android/blob/main/app/src/main/java/org/thoughtcrime/securesms/net/Networking.kt) refuses a socket when the configured proxy is invalid or networking is disabled and uses proxy-aware DNS. The [libsignal policy](https://github.com/0cwa/collieim-android/blob/main/core/network/src/main/java/org/signal/network/config/LibSignalNetworkExtensions.kt) marks a rejected **user** proxy invalid rather than clearing it. An optional **system** proxy may instead fall back to a direct connection if its configuration fails; do not describe every proxy as fail-closed.
- **Calling path:** With proxy information supplied to RingRTC, the Molly-derived WebRTC adaptation wraps TCP sockets in HTTPS CONNECT or SOCKS5 and disables UDP/STUN and local ICE candidate paths that could bypass the proxy. Collie's additional changes reject unknown proxy types and encode SOCKS IPv6 destinations (rejecting unsupported address families). This describes implemented safeguards, **not** a verified end-to-end guarantee that calls or other app traffic stay inside a configured proxy.
- **Bounded regressions:** The pinned libsignal diagnostic recorded all four native proxy-mode tests passing. The application has [socket fail-closed tests](https://github.com/0cwa/collieim-android/blob/main/app/src/test/java/org/thoughtcrime/securesms/net/MollyProxyFailClosedTest.kt) and [mocked libsignal policy tests](https://github.com/0cwa/collieim-android/blob/main/core/network/src/test/java/org/signal/network/config/LibSignalProxyPolicyTest.kt). The [unknown-type](patches/test_webrtc_unknown_proxy.py) and [SOCKS IPv6](patches/test_webrtc_socks_ipv6.py) harnesses compile extracted production C++ with stand-ins; they do not open sockets or run full WebRTC. The current app JVM suite is **not claimed passed**: its separate native host-test JNI input is still unavailable.
- **Build is not runtime proof:** [PR #45](https://github.com/0cwa/collieim-android/pull/45) records an exact-source **local unsigned APK** build; [native publication acceptance](https://github.com/0cwa/collieim-android/blob/main/build-inputs/native-publication.json) records immutable native input readbacks. Neither proves independent native reproduction, full proxy/call traffic containment, an API 35 runtime smoke, or MollySocket acceptance. Those tests remain unperformed for this candidate; do not equate source/build checks with behavioral acceptance.
